# Backup and recovery

ZIP format v1: `manifest.json` plus optional `assets/<portable-id>.img` originals. JSON is capped at 8 MB/depth 16, archive at 6,000 entries/1GB expanded, images at 80 MB. Unknown paths, directories, duplicate entries, dangling memberships, invalid destinations, invalid scene formulas, unsupported versions, and hash mismatches are rejected before database mutation. Every included image is SHA-256, size, and decode verified; already-installed originals are also rehashed before being trusted. The ordinary image re-import path uses the same integrity gate and copy-on-write file replacement, retaining prior bytes if corruption is detected. Image/scene metadata is merged in a Room transaction; wallpaper writes use the same repository maintenance lock. Backup originals are installed copy-on-write under new private filenames: existing artwork bytes are never overwritten, and newly installed files are removed if the Room transaction rolls back. An abrupt process interruption may still leave an unreferenced new file, but not replace an existing original. No source originals are deleted or arbitrary archive paths extracted. Imported same-ID rules and scenes are remapped without replacing local records, and repeated imports of identical records are deduplicated. Malformed backups with duplicate rule or scene IDs are rejected before database mutation.

Contains: artwork names/hash/dimensions/provenance/attribution/license/tags/favorites/exclusions, collection membership, orientation-specific editing sidecars, per-screen selection/interval/filter/queue state, rules, scene manifests/variables and workspace preferences. Does not contain remote credentials, signing keys, device SAF grants, private source URIs, or Android internal database files. Historical receipts, old scene revisions and provider credentials are not included yet (tracked limitations).

When including originals in a backup, the exporter excludes missing, quarantined or SHA-256-mismatched originals while retaining their metadata. Those assets restore quarantined unless verified bytes are available. The Library integrity action also hashes originals instead of merely decoding them, so modified-but-renderable files cannot be incorrectly unquarantined.

**Metadata-only is the default.** Original artwork export requires a clear opt-in and user-chosen SAF destination. Metadata-only restores show missing assets as quarantined until matching originals are re-imported. Exact hashes preserve identity; collisions are remapped. Restore pauses imported screen schedules/rules and never calls a wallpaper setter. Existing customized Home/Lock/Both destination rows are not overwritten; only untouched default destination records accept disabled/paused imported settings. Existing customized accessibility, performance, visual, and live wallpaper preferences are preserved; only a pristine local workspace may import visual preferences. Remote-command permissions are never restored. Users must review destinations and explicitly resume. Existing unrelated assets remain intact.

Editing sidecars are JSON subsets tied to SHA-256 rather than machine paths. Import applies only to existing matching artwork, preserving original image content. No new assets or broad permissions are required.

Sanitized diagnostic export is a separate format: only API/capability states and aggregate counts/storage totals. No names, paths, source URIs, location, artwork, personal health, network identifiers, or credentials.
